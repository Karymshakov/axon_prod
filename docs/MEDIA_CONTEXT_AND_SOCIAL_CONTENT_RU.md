# Медиа-контекст для лидов: сторис, посты, скрины, видео

## Цель

Когда клиент присылает фото, скрин, отвечает на сторис/актуальное или пересылает пост, CRM должна понять контекст без фантазий:

- что это за объект: номер, бассейн, кафе, ивент, территория;
- если номер, какая категория: `comfort`, `standard_twin`, `family` и т.д.;
- какие playbooks/tools нужны для ответа;
- насколько система уверена;
- нужно ли уточнить у клиента или передать менеджеру.

Vision-модель не должна напрямую отвечать клиенту. Она или дешевый hash-слой должны только создать структурированный `media_context`; основной агент отвечает уже на основе playbook/tool-контекста.

## Где заполняется база контента

Есть два слоя.

### 1. HotelMediaItem

Это проверенная медиатека отеля: фото номеров, бассейна, кафе, территории. Она уже есть в проекте.

Ее заполняет команда/менеджер, потому что это “эталонные” медиа, которые ИИ может отправлять клиентам и использовать как источник истины.

Для каждого элемента важны:

- `category`: rooms, pool, cafeteria, conference и т.д.;
- `room_category`: comfort, standard_twin, family и т.д.;
- `description`;
- `tags`.

Для этих фото строятся бесплатные perceptual fingerprints: `phash`, `dhash`, `ahash`, `center_phash`, `colorhash`.

### 2. SocialContentItem

Это реестр опубликованного Instagram-контента: post, reel, story, highlight, event/campaign.

Он заполняется автоматически и затем проверяется менеджером:

- auto sync из Instagram API: посты/рилсы/активные сторис;
- webhook, если клиент ответил на сторис/поделился медиа, которого еще нет в базе;
- manual, если менеджер хочет заранее создать ивент/кампанию.

Менеджер не должен вручную заносить каждую сторис с нуля. Его задача - открыть очередь `needs_review` и быстро подтвердить смысл:

- “это бассейн”;
- “это номер Comfort”;
- “это Nomad Run Camp”;
- “если клиент спрашивает, использовать playbook `nomad_run_camp`”;
- “в ответе мягко уточнить даты/кол-во гостей”.

## Как обрабатывать разные кейсы

### Клиент скинул нашу же фотку или скрин

1. Сохраняем файл в `LeadActivity.metadata.file_url`.
2. Строим fingerprints входящего изображения.
3. Сравниваем с `MediaFingerprint`.
4. Если совпадение уверенное, пишем в `metadata.media_context`.
5. Агент получает `metadata.ai_text`, например:

```text
Guest sent media. The system resolved this media context:
- topic/category: rooms
- room_category: comfort
- matched_content_title: Comfort room
- confidence: 0.94
- confidence_policy: you may use this context as verified
Guest text/caption: сколько стоит?
```

### Клиент ответил на сторис/пост

1. Из webhook вытаскиваем `story_id`, `media_id`, `share_id`, если Meta прислала.
2. Ищем `SocialContentItem.external_id`.
3. Если нашли, берем категорию, room_category, playbook_keys, reply_guidance.
4. Если не нашли, автоматически создаем `SocialContentItem` со статусом `needs_review`.
5. Клиенту не нужно ждать менеджера, если контекст понятен. Если не понятен, задаем уточняющий вопрос.

### Сторис живет 24 часа

Сторис хранится как `SocialContentItem(content_type="story")`.

- пока активна: `status=active`;
- после 24 часов или исчезновения из API: `status=expired`;
- если она попала в актуальное, создается/обновляется отдельная запись `content_type="highlight"` или ставится `parent_external_id`.

Даже если сторис истекла, старые лиды сохраняют свой `media_context` в `LeadActivity.metadata`, поэтому история диалога не ломается.

### Актуальное

Актуальное лучше считать устойчивым контентом, а не временной сторис.

Менеджер один раз подтверждает тему highlight:

- бассейн;
- номера;
- питание;
- ивенты;
- правила/цены.

Дальше ответы на это актуальное используют тот же контекст.

### Видео и рилсы

Нельзя брать только первые 5 секунд: там часто hook, лицо, текст или монтаж.

Нужно хранить несколько кадров:

- thumbnail;
- кадр 0 сек;
- кадр 3 сек;
- кадр 7 сек;
- кадр 12 сек;
- кадр 20 сек;
- keyframes по смене сцены, если доступно.

Для каждого кадра строятся fingerprints. Если ролик вручную помечен как `pool`, это главнее кадров.

### Ивенты: забег, лагерь, спецпредложение

Для ивентов используется `SocialContentItem(content_type="event")`.

Если ивент простой и уже есть playbook, например `nomad_run_camp`, достаточно связать content item с этим playbook key.

Если ивент живет как отдельная мини-воронка, лучше добавить:

- дату/период;
- условия участия;
- цены/пакеты;
- что входит;
- дедлайн;
- кому передавать;
- короткий reply_guidance.

Это не нужно делать отдельным агентом, пока ивент не требует сложного сценария. В большинстве случаев достаточно `SocialContentItem + playbook + reply_guidance`.

## Политика уверенности

Если confidence высокий: агент может использовать контекст как проверенный.

Если confidence средний: агент формулирует осторожно:

```text
Похоже, вы спрашиваете про номер Comfort. Подскажите даты заезда/выезда, и я рассчитаю стоимость.
```

Если confidence низкий или совпадения нет:

```text
Подскажите, пожалуйста, что именно вас интересует на фото: номер, бассейн, стоимость или условия бронирования?
```

Если после уточнения клиент все равно не дает понятного запроса, или вопрос нестандартный/рисковый, тогда задача менеджеру.

## Что уже реализовано в backend

- `SocialContentItem` - реестр опубликованного соцконтента.
- `MediaFingerprint` - отпечатки для распознавания скринов/повторных фото.
- `rebuild_media_fingerprints` - management command для пересборки отпечатков.
- `sync_instagram_social_content` - management command для синка Instagram posts/reels/stories.
- `hotel_media.sync_instagram_social_content` - Celery beat task, по умолчанию каждый час.
- `/api/social-content/` - API для очереди проверки контента.
- `/api/social-content/sync-instagram/` - ручной API-триггер синка Instagram-контента.
- `/api/media-fingerprints/` - read-only API отпечатков.
- `resolve_activity_media_context()` - сервис, который обогащает `LeadActivity.metadata`.
- Instagram webhook сохраняет story/media/share контекст, если он есть в payload.
- Telegram/WhatsApp/Instagram могут использовать `metadata.ai_text` вместо плейсхолдера.
